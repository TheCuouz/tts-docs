Docs / TTSCore

Installation

What you need

  • Java 21. The same Java a Paper 1.21 server already runs on.
  • A Paper 1.21.x server, new or existing. TTSCore is Paper 1.21.11 with our changes on top, so worlds and plugins that run on Paper run here.

Swapping the jar

  1. Stop the server and make a backup of the folder.
  2. Put the TTSCore jar next to your current server jar.
  3. Point your start script at it:
java -Xms2G -Xmx4G -jar ttscore.jar nogui
  1. Start the server. On first start it writes ttscore.yml in the server root, with every setting at its vanilla value and a comment above each one.
  2. Put your licence key in that file and run /ttscore reload:
settings:
  license-key: "TTS-XXXXX-XXXXX-XXXXX-XXXXX"

To keep the file somewhere else, start with --ttscore-settings path/to/file.yml.

Checking it took

Run /ttscore version. It answers with the TTSCore build the server is running and the state of the licence.

At this point nothing in the game has changed. That is on purpose: you turn settings on one at a time and you know which one did what.

A first change you can see

raid.tnt.fuse-ticks is a good test because the result is visible in two seconds. In ttscore.yml:

world-settings:
  default:
    raid:
      tnt:
        fuse-ticks: 20

Then, in game:

/ttscore reload
/summon tnt ~ ~ ~

The TNT goes off after one second instead of four. Set it back to 80 and reload again.

The licence key

The key is the one shown after checkout and on your account page at the store. The server checks it in the background when it starts and when you reload.

  • No key, or a key the store rejects: the server starts and runs as plain Paper. The settings on this site stay locked until a valid key is in the file.
  • The store cannot be reached: the server keeps running with its settings. A network problem on either side never takes your cannons away.

Going back

Stop the server and start it with your Paper jar. ttscore.yml is ignored by Paper and nothing else was touched.

If you want vanilla behaviour in one world without leaving TTSCore, set raid.enabled: false in that world's block.
